## Design Context

### Users
The primary user is an Obsidian knowledge worker organizing a long-lived personal collection of web pages, articles, tools, images, and annotations. The core job is to see relationships at a glance and directly manipulate the collection without leaving the note or canvas.

### Brand Personality
Calm, consistent, and direct. The interface should feel like a dependable native Obsidian work surface: personal enough to arrange freely, but restrained enough to remain useful as the collection becomes dense.

### Aesthetic Direction
Obsidian-native and theme-adaptive, with a quiet desktop-canvas metaphor. Reuse Obsidian semantic colors and typography, and express plugin decisions through the scoped `--wd-*` tokens documented in `DESIGN.md`. Avoid ornamental gradients, glass effects, unrelated card styles, and a separate branded component-library aesthetic.

### Design Principles
1. Make direct manipulation discoverable: draggable and resizable objects need visible handles or unambiguous hover states.
2. Preserve spatial trust: writes, reloads, and new-object placement must not cause objects to jump, overlap completely, or disappear outside the visible area.
3. Keep component semantics consistent across the main canvas and embedded note canvases.
4. Prefer Obsidian-native menus, controls, theme variables, and accessibility behavior before adding dependencies.
5. Preserve user data when references disappear: show a missing state and keep annotations unless the user explicitly deletes them.
